## 0.9.0rc1 – unreleased

### Added
- **A node array is declared, and `levels` makes it a categorical attribute.** A parameter whose `measure` is an array's path in the network's companion declares that array. On `node_template` it runs over the nodes, node `i` taking entry `i`, is read as `network.nodes.<name>` and is not copied onto each node; on the network it is any other array, such as a vocabulary. The new `Parameter.levels` names the network parameter whose entries, its `value` or the array its `measure` names, a categorical attribute's codes index, and a `levels` naming no network parameter is refused. A node selection serves an array declared on the network whole. The 23 curated Schaefer2018 networks declare each parcel's functional network (`parent_index`) as a code into `functional_network_labels`, so a selected Schaefer2018 network now saves, where its 34 network names, read as per-node data, refused it. A network named by its atlas alone (`parcellation: {atlas: ...}`) carries what its curated network declares and each region's `hemisphere` from the atlas's terminology, and a save of it reads back with them when no atlas file can be found.
- **A vocabulary declares its hierarchy: `Parameter.parent`.** It names the network parameter that gives each entry of the vocabulary its parent: one code per entry, a code into the vocabulary that parameter's `levels` names, or `-1` for an entry with no parent, as the regions of an atlas sit within its lobes. A `parent` naming no parameter or one without `levels`, a count of codes other than the vocabulary's, a code outside the coarser vocabulary and a code that is no finite number, named with the entry it is given to, are refused when the network is resolved, and when it is saved for arrays set after it was built. A save keeps the hierarchy in every format, and a network that takes a curated network's categorical attributes takes the vocabularies above them as well.
- `tvbo migrate-iris <paths>` rewrites the curated-record IRIs of YAML specs, and of the fenced YAML in Markdown and Quarto pages, into their `tvbo:<folder>/<file stem>` form, a record named by its `name:` or by its stem in another case included (`tvbo:observation_models/BOLD_TVB` becomes `bold_tvb`), leaving every other byte as written. A name the slot it sits in cannot place (`tvbo:Linear` is both a model and a coupling function; in the string slot `connectome`, `tvbo:DesikanKilliany` is both an atlas and the connectome filed under it) is reported for a person to settle; `--check` writes nothing and exits 1 when anything would change.
- **A parameter starts where it declares.** On tvboptim a dynamics or coupling parameter with a `distribution` sampled over space is drawn when the network is built, one value per node or, for a coupling parameter of the graph's shape, one per connection on the network's edges, keyed by `execution.random_seed` unless the distribution has its own `seed`. Each cell of an `execution.random_seed` axis draws the start a run declared at that seed draws, a tuning algorithm starts from it, and an on-device cohort starts every subject from it. The trials of an `n_trials` ensemble share their cell's draw, and `Distribution.axis: trial` gives each trial its own instead. `Parameter.equation` gives a parameter its value from the other parameters of its owner, evaluated once at the same moment, which is how two parameters share one draw. NetworkDynamics.jl draws a per-node dynamics parameter uniform on its distribution's `domain` under the same seed rule. A backend honours the kinds of start its `ExportFormat.parameter_starts` names and refuses every other one by name when it renders or runs; a format registered without the field honours none. Refused as well: a parameter with a second definition of its value (a `value` beside an equation, a value a node declares for it, even the dynamics' own, a `source`, `producer`, `used` reference or a `measure` read from another experiment, a free parameter's `initial_value`), an equation that reads a parameter whose value comes from such a second definition, an exploration axis on a parameter with a start or on one its equation reads, a distribution that does not say what to draw or a `domain` on an unbounded normal, a draw per trial in an exploration that wires an algorithm into each cell, and a seed the generated module cannot key a draw with (outside 0 to 2**32 - 1).
- **An analysis can be transient: `Analysis.persist: false`.** It runs in dependency order like any other and its outputs feed every analysis that reads it in the same run, but its container goes to a per-process temporary directory outside the study that is removed at exit: no container, no sidecar, no provenance record is left under the study, the manifest's staleness pass skips it, and whatever reads it recomputes it. A figure, a report or a kit reads containers and is refused a transient analysis by name; only the analyses and experiments of the same run read it. Individual-level tables a study must not keep are declared this way, and only the reductions downstream persist.
- **A printed statistic states its significance: `Annotation.significance`.** The asterisks a paper sets after a statistic (`r=0.89***`) are counted from a p-value the render reads, `significance: {used: {analysis: …, output: p}}`, one per threshold in `levels` the value is below (0.05, 0.01 and 0.001 unless declared). On the panel only: a `placement: caption` annotation that declares one is refused. `bsplot.load_scalar` and `bsplot.significance_marks` are the two public helpers the render script calls.
- **A reference reads a layer of a network.** `used: {iri: <network file or curated id>, output: weight}` returns the named edge layer or per-node quantity as the network delivers it: read from wherever the network declares it, passed through the network's transforms and labelled by node. The file is a sidecar (`.yaml`, `.yml`, `.json`) at the path as written or against the study root; a curated network is named by its exact id. A network that reads per subject from a cohort gives a per-subject run that subject's layer and a study analysis every member's, stacked on `subject`, so a rule a network declares is never restated in the analysis that needs its result. The analysis is scheduled after the analyses and experiments the network reads, and it goes stale with the network's declaration, its array file and the cohort's members. A spec fragment named this way is read as the study that includes it reads it, with its paths against the study root.
- **`tvbo run --no-analyses`.** A study's experiments run with only the analyses they read; the other analyses and the figures are skipped, and the analysis containers left stale are named, as for a run narrowed by `--experiment`. A `--limit` probe of the simulations alone uses it; without it the analyses and figures run on the sample. A study of studies refuses it, since each nested study runs end to end.
- `_function` joins the spec-suffix vocabulary, so a transform two networks share is one `spec/desc-<name>_function.yaml` each includes.
- **A shape names its sizes.** A parameter's or a state variable's `shape` is a tuple of integers, `n_nodes` and sizes, where a size is a parameter of the same dynamics holding an integer that nothing draws, sources, produces, fits, tunes, holds or sweeps: `W: {shape: "(n, n)"}` beside `n: {value: 100}`. One reader (`tvbo.codegen.dims`) parses and sizes every shape, for the tvboptim stage marking, a sourced parameter's shape check and the report, and tvboptim's generated module binds each size as an integer constant instead of tracing it as a parameter. `per_node_dims` types a per-node equation by the element axes each operand carries by name, so `W_out @ x` with `W_out: (n_nodes, n)` contracts to one value per node while `W @ x` with `W: (n, n)` keeps `n`, and the parser reads `a @ b` as `matmul(a, b)`.
- **A continuation states what it holds: `Continuation.held_parameters`.** Each entry `{parameter, algorithm}` holds a parameter to the target of an algorithm's objective along the branch, as FIC holds `J_i`. BifurcationKit continues it; numcont and pyrates-bifurcation refuse it by name, and an entry whose algorithm has no target, or no update rule acting on the parameter, is refused.
- **An axis is named in an expression.** `sum_axis(x, node)`, `rankdata(x, time)`, `normalize(M, variable)`, `slice_axis`, `slice_from` and `shape` take the name of one of the operand's axes where those are known, and `tvbo.codegen.dims` follows a value's axes through the whole expression (elementwise keeps them, a reduction drops the axis it names, `transpose`/`matmul`/`outer`/`welch` re-order or replace them, indexing drops the indexed ones). A derived observation's `equation` steps, and a monitor pipeline's over the model trajectory, are declared from that, so the result arrives keyed by the axes that survive. A name no axis carries is refused at codegen, naming the observation and step and listing the operand's axes; an axis position must now be an integer literal (`shape(x, 0.0)` is refused).
- **A study states its look once: `SimulationStudy.theme`.** One `Theme`, usually a `spec/desc-<name>_theme.yaml` fragment named with `!include`, is the rule every figure in the study's `figures:` list is drawn by, whichever file the figure record came from; a nested study that states none takes its parent's. A figure overrides it where it differs, through its own `theme` or the look slots it carries directly, and each layer states only what it changes: the shipped theme, then the house rule on `auto_format: true`, then the study's theme, then the figure's. `_theme` joins the spec-suffix vocabulary.
- **The axis rule is declared.** `Theme.ticks` says who places an axis's ticks: `native` (the backend's locator, nothing moves), `round` (multiples of a round step from `tick_steps`, at most `max_ticks`) or `declared` (only the ticks each panel gives; the render refuses, naming every axis that gives none). `Theme.axis_ends` says where an autoscaled axis ends: `data`, `ticks` (a tick at both ends, however far) or `near` (an end moves to a tick only within `end_tick_reach` of the data, never leaving fewer than three ticks). `spines`, `spine_offset` and `spine_trim` say which sides are drawn, whether the two scale-bearing ones stand off the plot and whether each ends on its outer ticks; `align_labels`, `colorbar_ends` and `colorbar_outline` complete it. What a panel declares (`xticks`, `yticks`, `nbins`, limits, a log scale, an image's extent) and the ticks a custom drawer fixed are never re-placed. `tvbo.plot.axis_rule` is the implementation, callable on any matplotlib figure.
- **The rest of a style sheet has Theme slots.** Type (`font_size`, `font_weight`, `label_scale`, `label_weight`, `tick_label_scale`, `title_scale`, `title_weight`, `title_loc`, `legend_scale`, `math_font`, `unicode_minus`), number notation (`tick_format`, `exponent_as_power`), ticks and margins (`mirror_ticks`, `axis_margin`), strokes (`marker_edge_width`, `bar_edge_width`, `line_cap`, `errorbar_cap_size`), legend (`legend_loc`, `legend_label_spacing`, `legend_handle_text_pad`, `legend_marker_scale`), grid (`grid_width`, `grid_style`, `grid_below`), panel letters (`panel_numbers`, `panel_number_format`, `panel_number_case`, `panel_number_loc`, `panel_number_offset`, `panel_number_scale`, `panel_number_weight`) and output (`dpi`, `trim_margins`, `pad`, `format`, `transparent`, `editable_text`, `layout_engine`, `style`). `opts` takes any backend setting no slot names. A test pins every Theme slot to a consumer, so none can be accepted and ignored.
- **`tvbo.__all__` and `__dir__`.** `dir(tvbo)` now lists the API rather than the stdlib modules (`os`, `shutil`, `tempfile`, `warnings`, `logging`) that `import tvbo` bound as a side effect of its own setup. `__all__` is what SemVer covers; see the new *What is public* section of `CONTRIBUTING.md`.
- **`tvbo/py.typed`.** The package is annotated throughout, but without PEP 561's marker file every downstream `mypy` ignored those annotations.
- `SECURITY.md`, issue templates and a PR template.
- Schema-declared `aliases:` now resolve at load time, so `dt` (for `Integrator.step_size`), `number_of_regions`, `righthandside`/`lefthandside` and `components` are accepted where the schema says they are. Resolution happens per class, so a free-form key — a model parameter named `dt`, a `components:` list under an unrelated block — is never rewritten.
- Experiment YAMLs support `!include` and merge keys (`<<: *anchor`), which networks and studies already had.
- `BrainAtlas` carries the shared `provenance` slot, as `Network` does, so an atlas sidecar records the inputs, activity and checksum of its label image in the same file as its label table.
- `BrainAtlas.description` (the shared `dcterms:description` slot), `ParcellationEntity.volume` in mm³ (`wdt:P2234`, with its UCUM unit and QUDT quantity kind) and `Provenance.how_to_acknowledge` (`schema:creditText`, BIDS `HowToAcknowledge` as an alias), so an atlas sidecar states what the atlas is, how large each labelled region is and which acknowledgements its sources oblige a reuser to print; licence and references stay on `provenance`.
- Expression primitives for a study's statistics, each checked against the library a reader would reach for: `welch`, `hann` and `rfftfreq` (a power spectrum, as `scipy.signal.welch`), `rankdata` (ranks, so a Spearman correlation is `pearson` of ranks), `pinv`, `interp`, and `upper_triangle(M, k)`, the entries on and above a matrix's `k`-th diagonal, so an FC agreement is `pearson(upper_triangle(fc, 1), upper_triangle(empirical_fc, 1))` over the off-diagonal half once.
- Curated functions in `tvbo/database/functions/`, named by `iri: tvbo:functions/<name>`, so a study's statistic is defined once and every study that names it computes the same quantity: `FCCorrelation` (Pearson over the off-diagonal upper triangles of two FC matrices), `WelchPSD` (scipy's default Welch), `SoftPeakFrequency` (a differentiable peak frequency), and `SetMean` and `SetCosine` (a per-node value against a node set given as a per-node membership). Each is checked against scipy or numpy. The `Function` registry category now points at this folder; it pointed at `observation_models/`, which holds no functions.
- **A study-level analysis names a curated function by `iri`, and three statistics are curated.** An `Analysis`, like every `FunctionCall`, written with `iri: tvbo:functions/<name>`, or with any other spelling that names that function, the unscoped `tvbo:<name>` among them, takes that function's equation or callable and the descriptions and defaults of its arguments, and states only its own arguments. A scoped `iri` that names no curated function is refused, and so is an invocation that names a function and states an `equation`, `callable`, `class_call` or `function` of a kind that function does not record. An unscoped `iri` that matches no curated function merges nothing, as on every other class, and is refused where the invocation states none of those four itself and no `type`, since it would run nothing. An analysis's sidecar records the equation or callable it ran and does not yet record the `iri` it was expanded from. `GroupedCorrelation` cuts the units of a named dimension into groups by a score or by another variable, in bins of equal width or runs of equal size, and returns the group means, standard deviations, standard errors and sizes, the least-squares line, `r` and `p` over the group means and over single units, once per element of every other dimension its inputs carry. `FalseDiscoveryControl` adjusts a family of p-values by Benjamini-Hochberg or Benjamini-Yekutieli, as `scipy.stats.false_discovery_control` does, and marks the tests kept at a rate; a NaN is no test, any other value outside 0 to 1 is refused, and so is a rate `q` that is not one number above 0 and below 1. `Histogram` counts values in equal-width bins, optionally only those a mask marks, a labelled mask paired with labelled values by label. The three record a callable in `tvbo.analysis.statistics` rather than an equation and are checked against scipy and numpy.
- An `errorbar` figure mark: one vertical bar per x between two edges, the data contract of `band` drawn as separate segments, since a band filled between discrete groups implies values between them that were never measured.
- `Algorithm.update_start`: simulated time, counted from the start of each stage, before which a tuning algorithm's update rules are not applied.
- **`Cohort`: a named subset of a dataset's subjects.** `Dataset.cohorts` names the subjects a group-level quantity is defined over, and a study lists its datasets under `datasets:`. A reference reads a cohort by identifier, `used: {cohort: <id>, query: {...}, output: weight}`: each member's own file is found under the dataset's `bids_root` by the BIDS `query`. A study analysis gets the whole cohort, stacked on `subject` in member order and aligned by node label; a per-subject run gets its own member, whether a network layer, a transform argument, a sourced parameter, a stimulus recording or an exploration builder argument reads it, and a subject outside the cohort raises. A cohort mean or presence count is then an ordinary equation analysis (`aggregate: {over: subject}`), whose container records the cohort and goes stale when the cohort's members change.
- **A network declares where a layer and a transform argument come from.** A template edge takes `used:` (`{label: weight, used: {cohort: ..., reconcile: by_label}}`), so a model network reads each subject's own connectivity onto its own node order, and a transform argument takes `used:`, so a normalisation that depends on a cohort aggregate is stated as an equation over the raw matrix and applied on read. `Network.bind_references(subject=..., datasets=..., results_root=...)` states what such references resolve against; a sourced layer read with nothing bound raises, and is read only when that layer is asked for. A per-subject run (`tvbo run --subject`) binds its own subject, so one network spec serves a whole cohort: the generated tvboptim code is the same for every subject, is rendered without one, applies the declared transform to the raw weights it is handed, and takes each `used:` argument from the run (`run_experiment(network_data=...)`) instead of embedding it. A layer or argument read from another experiment orders a workflow plan after that experiment, as a sourced parameter does.
- `_dataset` and `_dataref` join the spec-suffix vocabulary, so a study's dataset fragments and the reference fragments its analyses and networks merge validate by name (`tvbo validate study`).
- **A network declares some of another's nodes: `Network.node_selection`.** `keep` or `drop` names nodes by label (a declared alias counts) and the network is those nodes of its source, in the stored order and numbered from zero: every edge layer and edge parameter, dense or sparse, every per-node array, the listed edges, tract lengths and the delays computed from them, the node list and the labels follow. A reference that reconciles by label follows too; a positional one arrives in the selected count or is refused with both counts, and so does a layer a `producer:` builds; a per-node parameter read by `source` and `measure` from a network with more nodes is aligned to the kept nodes by label. Node and edge objects passed in are copied before they are renumbered. Refused, by name: a label no node carries (with the labels that are there, or the nearest for a long list), a label several nodes share, a label listed twice, `keep` together with `drop`, a selection that leaves no node, a value declared for a dropped node, a route to another network, a surface mesh. A saved network, a dumped record and a kit store the selected network with the selection kept and marked `applied`, so each reads back as the network that ran. A saved network and a kit read back beside the selected arrays and select nothing again; a dumped record whose source still delivers the dropped nodes (it names the unselected companion, a curated network or an atlas) is selected again by label on load and has to keep exactly the nodes it lists, or it is refused as written from a source that has changed since. A dumped selection of a generated graph is refused, since the graph is generated again at the kept count; `save` writes its arrays.
- **A list of participants is read from a file: `Cohort.members_file` and `Dataset.subjects_file`.** The file gives what the typed list gives (`.yaml`, `.yml` and `.json` hold the content an `!include` would insert, a `.tsv` or `.csv` is a participants table read by `participant_id`, any other file holds one identifier per line; a byte-order mark is ignored and a table row with a value but no participant is refused by its row number), so the list stays out of the recipe and out of everything a load, a report or an error prints: messages about such a list give counts and positions. A relative path is read from the directory of the experiment or network file the dataset is part of, also when the dataset is `!include`d from another directory, then from the study root; a file at neither is refused with both places. A kit writes each list its experiment reads beside the frozen spec, whether or not it bundles the dataset's files, the frozen dataset names the file, and the frozen cohort's description states how its members were admitted; two lists that would be written to one file name are refused.
- **A cohort is admitted by a rule: `Cohort.rule`.** `{measure, grouping, n_groups, group}` takes one group of the candidates' values of a measure in the table `Dataset.phenotype_file` names (or the rule's own `phenotype_file`), a `Phenotype` sidecar or a `.tsv` or `.csv` table, any other file being refused by its suffix; the candidates are the members of the cohort `of` names, else the dataset's subjects, else every row of the table. `equal_width` cuts the range from the lowest to the highest candidate value into bins of one width, closed below and open above with the last closed on both sides; `equal_count` cuts the ascending order into groups whose sizes differ by at most one, the larger first, ties in the candidates' order. Groups are counted from 1 for the lowest values. A candidate without a finite value is refused with the count, or left out under `missing: exclude`; an empty group, a group outside `1..n_groups`, a width over one value and a cycle through `of` are refused. Members are computed at load and stored nowhere.
- A per-subject fan-out narrows itself to the subjects its network can be built for. When a network reads a layer from a cohort per subject, `dataset_subject_ids()` keeps the dataset's subjects that are members of every such cohort, and `subject_selection()` states how many were kept and which were excluded. The workflow plan carries that statement into `tvbo workflow plan`, its `--json` payload and the kit README. Planning such an experiment when no dataset declares its cohort raises; the planner no longer drops the subject axis silently.
- A workflow kit carries a network read per subject. Its dataset bundle holds each fan-out subject's cohort files, beside its dataset targets when it has any, the frozen experiment's own dataset declares the cohort with the members the kit runs, and the analysis containers the network's transforms read are staged into the kit's results. A frozen network keeps the `used:` references of every layer its binding has not read, and its companion holds no stand-in values for them.
- **An annotation can be written into the caption instead of onto the panel.** `placement: caption` on a panel's, inset's or grid cell's annotation formats its `text` with the value its `used:` binding reads and appends the sentence to that panel's clause of the composed caption, so a sample size is stated as a computed number in the legend rather than drawn on the data. The caption staleness check compares a committed caption with the number left free, and with the sentence of a panel that declares a `placeholder` either present or absent, so a build without the containers still checks the prose.
- **The Zarr network companion has an extra: `pip install "tvbo[zarr]"`.** `binary_format="zarr"` imports Zarr when a network is saved or read, and no extra named it; `zarr` needs Zarr 3 and is part of `all`, so the Zarr saves are tested wherever the full install is.

### Changed
- **`Network.node_template` is a `NodeTemplate`.** The new class holds the node slots a template may set, and `Node` has the same slots plus the slots of one node, `id`, `label`, `position` and `region`, without being a `NodeTemplate`. A template carries no `id` (the 23 curated Schaefer2018 networks no longer write `id: -1`), and one that sets a per-node slot is refused, naming it, in both generated forms and in the loader, a built `Node` given as the template included, where it was ignored, and LinkML's own validator refuses such a template as well. The `id: -1` every saved template carried is dropped when a network is read, and only that value, so a network saved before, a copy of a curated sidecar in a kit included, still reads.
- A save keeps a network's `tractogram`. It was dropped as a directive that rebuilds the connectome, but it states which tractography the connectome was reconstructed from, and a reload reads the companion first, as it does beside `parcellation`, which a save already kept.
- The merged ontology's header is stamped by `make gen-merged` from `ontology/tvbo-header.ttl`: The Virtual Brain Ontology (TVB-O), CC BY 4.0, its four creators by ORCID, each named by `schema:name` (Leon Martin, Konstantin Bülau, Leon Stefanovski, Petra Ritter), the preferred prefix `tvbo` for `https://w3id.org/tvbo/`, the preprint's DOI, and the package version as `owl:versionInfo` and `pav:version`. It used to read "The Virtual Brain Data Model", version 0.4.0, under EUPL-1.2.
- Every TVB-O term the merged ontology's modules declare, the curated records included, is `rdfs:isDefinedBy <https://w3id.org/tvbo/tvbo.owl>`, which `ontology/is-defined-by.ru` adds in `make gen-merged`. The schema's classes named `https://w3id.org/tvbo/struct` and the NeuroML classes `https://w3id.org/tvbo/neuroml`, intermediate modules the merge dissolves, and every other term named none.
- Every TVB-O class and property of the merged ontology has an `rdfs:label`. One `gen-owl` leaves out, for an attribute that more than one class declares, is the name as written, qualified as every other slot label is, with the bare name in `skos:notation`: `abs_tol` reads "abs_tol (slot)" and `study/role` "role (study)". The LinkML annotation tags `collection_key` and `simple_dict_value` no longer reach the ontology as undeclared `tvbo:` predicates. The A-box's `hasParameter`, `hasStateVariable` and `hasDerivedVariable` are labelled by their names, `tvbo:SaddleNode` reads "Saddle-node", and a coordinate space's `anatomicalAxesOrientation` and `axesOrigin` are the SANDS properties the schema declares, where the A-box minted unlabelled `tvbo:` properties of the same names.
- **The repository states its licences file by file in `REUSE.toml`, with each licence text in `LICENSES/`.** Code and documentation are EUPL-1.2, which `__license__` and the file headers now name in that plain form. The ontology, the LinkML schema, whose every module declares `license: https://creativecommons.org/licenses/by/4.0/`, the copies of it the package ships and the curated records are CC BY 4.0, and a record that inlines third-party labels, coordinates or values adds its source's licence, such as `CC-BY-4.0 AND MIT` for Schaefer2018 parcels or `CC-BY-4.0 AND GPL-3.0-or-later` for the tvb-data sensors. A third-party data file carries its source's terms, among them the WU-Minn HCP Open Access Data Use Terms, the MGH-USC HCP Data Use Agreement, the PPMI Data Use Agreement, the FreeSurfer licence and the MNI ICBM 152 notice, and a file whose licence is not established is marked `LicenseRef-TVBO-Unresolved`, whose text asks that it not be redistributed beyond the tvbo distribution until its terms are established. `schema/openMINDS_tvbo/LICENSE`, an EUPL text inside the CC BY schema folder, is removed. `pyproject.toml` declares the licences of every file the wheel ships as one `license` expression and their texts as its `license-files` (PEP 639, so the build requires `hatchling>=1.27`), and `tests/test_reuse_license.py` fails when either names a licence too many or too few. `tvbo/` has no default licence, so the same test fails on a package file that no entry covers, and CI runs `reuse lint` (reuse 6.2.0). `CITATION.cff` gives the software's licence, `EUPL-1.2`, alone, since CFF reads a list of licences as a choice between them, and lists Konstantin Bülau's ORCID and Leon Stefanovski among the authors, and the schema's title is "The Virtual Brain Ontology" and its `version` the package's, which `scripts/release.sh` writes beside `__version__` and checks.
- **The PPMI 85 network records say how to cite PPMI.** Each lists PPMI (Marek et al. 2011) and the Lead-DBS PPMI 85 connectome (Ewert et al. 2017) in `provenance.references`, and the two acknowledgement sentences PPMI asks publications to carry, with the funding partners PPMI names, in `provenance.how_to_acknowledge`.
- A recipe that declares a parameter `distribution` sampled over space, or a parameter `equation`, is refused by name on tvb, jax and every other backend that cannot draw or evaluate it, where it used to integrate one constant on every node. On tvboptim `docs/Interoperability/NetworkDynamics.jl/yaml/kuramoto.yaml` now draws its natural frequencies `omega0` from Uniform(0.2, 1.0) per node, where it integrated 0.0 on every node.
- NetworkDynamics.jl seeds its draws with `execution.random_seed` where no distribution declares its own `seed` (it used 0), and refuses a per-node parameter start of a family other than Uniform, a steady-state search with one, two distributions in one module that resolve to different seeds, which its one random stream cannot honour, and a draw per trial.
- `tvbo workflow slurm|snakemake|nextflow` refuses an experiment any of whose references (a network transform's argument, a parameter, a stimulus, a builder argument) reads a layer from a network file through `used: {iri: <file>}`, naming the reference. A kit carries dataset files and result containers, not a network file a reference names; a layer read in an analysis travels with that analysis's container, and a curated network (`tvbo:<id>`) is installed with the package and is not refused.
- **A continuation branch is an xarray Dataset.** `BifurcationResult.branch` holds the branch keyed by `step` — `param`, the state variables, `stable`, `specialpoint` (a string variable, `""` where a step carries no special point) and the rest as variables — the same keyed container every other tvbo result uses, and every backend extractor (BifurcationKit, AUTO-07p, PyCoBi) builds it directly. `BifurcationResult.df` is now a read-only pandas view derived from it (assign to `branch` to change the data); `compute_voi`/`resolve_coords` take the Dataset and return arrays; an AUTO diagram of several sub-branches counts `step` once across all of them, with `branch_id` keeping them apart.
