## 0.9.0rc1 – unreleased

### Added
- **`tvbo.__all__` and `__dir__`.** `dir(tvbo)` now lists the API rather than the stdlib modules (`os`, `shutil`, `tempfile`, `warnings`, `logging`) that `import tvbo` bound as a side effect of its own setup. `__all__` is what SemVer covers; see the new *What is public* section of `CONTRIBUTING.md`.
- **`tvbo/py.typed`.** The package is annotated throughout, but without PEP 561's marker file every downstream `mypy` ignored those annotations.
- `SECURITY.md`, issue templates and a PR template.
- Schema-declared `aliases:` now resolve at load time, so `dt` (for `Integrator.step_size`), `number_of_regions`, `righthandside`/`lefthandside` and `components` are accepted where the schema says they are. Resolution happens per class, so a free-form key — a model parameter named `dt`, a `components:` list under an unrelated block — is never rewritten.
- Experiment YAMLs support `!include` and merge keys (`<<: *anchor`), which networks and studies already had.
- `BrainAtlas` carries the shared `provenance` slot, as `Network` does, so an atlas sidecar records the inputs, activity and checksum of its label image in the same file as its label table.
- Expression primitives for a study's statistics, each checked against the library a reader would reach for: `welch`, `hann` and `rfftfreq` (a power spectrum, as `scipy.signal.welch`), `rankdata` (ranks, so a Spearman correlation is `pearson` of ranks), `pinv`, `interp`, and `upper_triangle(M, k)`, the entries on and above a matrix's `k`-th diagonal, so an FC agreement is `pearson(upper_triangle(fc, 1), upper_triangle(empirical_fc, 1))` over the off-diagonal half once.
- An `errorbar` figure mark: one vertical bar per x between two edges, the data contract of `band` drawn as separate segments, since a band filled between discrete groups implies values between them that were never measured.
- `Algorithm.update_start`: simulated time, counted from the start of each stage, before which a tuning algorithm's update rules are not applied.
- **`Cohort`: a named subset of a dataset's subjects.** `Dataset.cohorts` names the subjects a group-level quantity is defined over, and a study lists its datasets under `datasets:`. A reference reads a cohort by identifier, `used: {cohort: <id>, query: {...}, output: weight}`: each member's own file is found under the dataset's `bids_root` by the BIDS `query`. A study analysis gets the whole cohort, stacked on `subject` in member order and aligned by node label; a per-subject run gets its own member, whether a network layer, a transform argument, a sourced parameter, a stimulus recording or an exploration builder argument reads it, and a subject outside the cohort raises. A cohort mean or presence count is then an ordinary equation analysis (`aggregate: {over: subject}`), whose container records the cohort and goes stale when the cohort's members change.
- **A network declares where a layer and a transform argument come from.** A template edge takes `used:` (`{label: weight, used: {cohort: ..., reconcile: by_label}}`), so a model network reads each subject's own connectivity onto its own node order, and a transform argument takes `used:`, so a normalisation that depends on a cohort aggregate is stated as an equation over the raw matrix and applied on read. `Network.bind_references(subject=..., datasets=..., results_root=...)` states what such references resolve against; a sourced layer read with nothing bound raises, and is read only when that layer is asked for. A per-subject run (`tvbo run --subject`) binds its own subject, so one network spec serves a whole cohort: the generated tvboptim code is the same for every subject, is rendered without one, applies the declared transform to the raw weights it is handed, and takes each `used:` argument from the run (`run_experiment(network_data=...)`) instead of embedding it. A layer or argument read from another experiment orders a workflow plan after that experiment, as a sourced parameter does.
- `_dataset` and `_dataref` join the spec-suffix vocabulary, so a study's dataset fragments and the reference fragments its analyses and networks merge validate by name (`tvbo validate study`).
- A per-subject fan-out narrows itself to the subjects its network can be built for. When a network reads a layer from a cohort per subject, `dataset_subject_ids()` keeps the dataset's subjects that are members of every such cohort, and `subject_selection()` states how many were kept and which were excluded. The workflow plan carries that statement into `tvbo workflow plan`, its `--json` payload and the kit README. Planning such an experiment when no dataset declares its cohort raises; the planner no longer drops the subject axis silently.
- A workflow kit carries a network read per subject. Its dataset bundle holds each fan-out subject's cohort files, beside its dataset targets when it has any, the frozen experiment's own dataset declares the cohort with the members the kit runs, and the analysis containers the network's transforms read are staged into the kit's results. A frozen network keeps the `used:` references of every layer its binding has not read, and its companion holds no stand-in values for them. Such an experiment cannot be frozen without a bundle.
- **An annotation can be written into the caption instead of onto the panel.** `placement: caption` on a panel's, inset's or grid cell's annotation formats its `text` with the value its `used:` binding reads and appends the sentence to that panel's clause of the composed caption, so a sample size is stated as a computed number in the legend rather than drawn on the data. The caption staleness check compares a committed caption with the number left free, and with the sentence of a panel that declares a `placeholder` either present or absent, so a build without the containers still checks the prose.

### Changed
- JAX's floor is 0.4.29, the first release whose `jnp.linalg.pinv` takes `rtol`, which the `pinv` expression primitive passes so numpy and JAX cut at the same singular value.
- **`PDESolver` is a `Solver`.** It inherits `method`, `abs_tol`, `rel_tol` and `step_size`; the duplicate `time_integrator` and the untyped string `tolerances` are gone. Migrate `time_integrator:` to `method:` and `tolerances:` to `abs_tol:`/`rel_tol:`; `dt:` still works as the alias of `step_size`.
- One reader resolves the noise amplitude for every backend (tvboptim, Brian2, NetworkDynamics.jl, Julia). Declare it as `parameters: {sigma: ...}` (a standard deviation) or `parameters: {nsig: ...}` (a dispersion, sigma = sqrt(2*nsig)).
- The openMINDS export walks `is_a`, so a subclass carries its inherited slots (`PDESolver` and `Integrator` had been exported without theirs).
- `tvbo workflow submit --cores N` overrides only the profile's *executor*. The kit still runs in the container its profile declares, instead of dropping the profile — and its bind mounts, retries and keep-going — entirely.

### Removed
**1.0 clears the deprecation backlog rather than carrying it.** Every name that warned in 0.5.x is gone; each had a replacement that was already the documented path, and the callers in `tvbo/`, `tests/` and `docs/` are migrated to it.

- `noise: {intensity: ...}` — the schema slot is removed, so a recipe that still declares it is rejected instead of silently read as a standard deviation. Use `parameters: {sigma: ...}`, or `parameters: {nsig: ...}` if the value was a dispersion (the two differ by sqrt(2D)/D). One reader, `utils.noise_sigma`, now knows exactly two spellings.
- `random=True` / `random_initial_conditions=True` on `Dynamics.get_initial_values`, `SimulationExperiment.run` and `collect_initial_conditions` — declaring a `distribution` on the state variable is the only way to ask for sampling. The flag sampled every variable's raw domain regardless of what the model declared. `plot.dynamics` spread its multi-trial starts through that flag; it now does so itself, which is where a plotting concern belongs.
- `Dynamics.to_lems()`, `SimulationExperiment.to_lems()` and `save_model_specification()` — use `NeuroMLAdapter(...)`, which emits validated XML rather than a `lems.Model` and covers constructs those never did.
- `Network.compute_delays()` → `calculate_delays()`; `Dynamics.add_coupling_term()` → `add_coupling_input()`; `Connectome` → `Network` (it was a subclass that added a warning and nothing else).
- `equation.piecewise2numpy()` / `piecewise2julia()` — use `codegen.code.render_expression(expr, format=...)`. `print_Piecewise` is the one handler every printer shares, emitting through each printer's `_where3` primitive (`<mod>.where` for numpy/JAX, `ifelse` for Julia). Both predated it, duplicated one backend each, and raised on any Piecewise with a symbolic condition — so neither could have had a working caller.

### Fixed
- **The 17 rec-MghUscHcp32 and rec-PPMI85 networks are recounted from Lead-DBS's original group connectomes.** They had been counted from `.tck` conversions of Lead-DBS's `data.mat` that grouped each streamline's points with an unstable sort, so most streamlines' points were out of order and one end lay inside the white matter: 30% of MGH-USC 32's and 61% of PPMI 85's streamlines ended outside every parcel, against 12% and 20% from the originals. The networks held two to four times too few streamlines (on HCPMMP1, MGH-USC 32 connected 23.3% of region pairs and now 42.9%, PPMI 85 12.8% and now 33.5%), and old and new weights agree only to Spearman ρ 0.41–0.92. Each network is recounted as it was first counted, `tck2connectome` with `-symmetric -zero_diagonal` on the same parcellation volume, which reproduces every old matrix exactly from the scrambled file (`scripts/rebuild_leaddbs_cohort_networks.py`); only the HDF5 edge data changes. Anything fitted to or validated against these networks needs rerunning.
- A network that names a `data_file` and also declares a template edge now opens the file. The declared edge counted as connectivity already held, so the companion was never attached and every other layer read as absent; and where the file was opened, an authored edge carrying `producer:` was replaced by the companion's edge list and never computed. Layers that are only declared no longer stand in for data, and one that states where its matrix comes from (`used:`, `producer:`) replaces the companion's layer of that name.
- An equation analysis honours `execution.precision`. It was accepted and ignored: JAX computed in 32 bits whatever was declared, so a `float64` analysis of 32-bit inputs returned 32-bit results. The schema's default precision is `float64`, so an `execution` block that names none now computes at 64 bits as well, with twice the memory of before. Its sidecar also states the `equation` and its `aggregate` now, where it recorded an empty `callable`.
- A fragment merged with `<<: !include` may itself contain `!include`. A merged include inside it was refused ("expected a mapping or list of mappings for merging"), and a plain one was read against the including file's directory instead of the fragment's own.
- A subject's file is found at any depth under `sub-<id>/`, not only directly in it, so a dataset that keeps files in BIDS datatype or session folders (`sub-01/dwi/...`) resolves. Discovery and resolution share one definition (`tvbo.data.cohort`).
- One integration method, one canonical name, whatever the recipe spells it. `rk4` is a method the schema advertises and the tvboptim adapter accepted, but the ontology holding the method's symbolic update expression knew only `RungeKutta4thOrder` — so a recipe spelling it `rk4` ran on tvboptim and died in the tvb and jax templates on `'NoneType' object has no attribute 'equation'`. `tvbo.utils.integration_method` now resolves every spelling to the one name, and an unknown one raises instead of falling back. The spellings had been written out five times (the adapter and four templates), disagreeing about which they accepted, and two of the templates resolved an unknown method to `Euler` — silently integrating a fourth-order recipe by a first-order scheme. There is one table now, and `tvbo.adapters.tvboptim.solver_class` raises for a method tvboptim has no solver for.
- Heterogeneous tvboptim runs: `Node.id` is resolved as an identifier rather than a row index (weights, lengths and delays alike), `execution.random_seed` reaches each group's noise, routes are keyed by coupling name so two edges naming one coupling are one route, and the declared noise sigma is used instead of a hard-coded 0.01.
- Brian2: a `random` current-pulse edge gets its own per-edge subset mask, so two pulses onto one population no longer collapse onto a single mask and fraction.
- Julia: a recipe declaring `parameters: {sigma: ...}` produces an `SDEProblem` rather than a silently deterministic `ODEProblem`.
- Bifurcation: periodic-orbit waveforms are actually recorded (`save_sol_every_step`), aligned to the branch's step axis.
- An `Edge`'s scalar `weight`/`delay`/`distance` slots are read by every backend, not only by pyrates.
- `DirectOntologyAPI` no longer raises `'str' object has no attribute 'storid'` on entities whose `requires` mixes entity references with bare names. `tvbo:requires` (an ObjectProperty holding entities) and the NeuroML ingest's `requires` (an AnnotationProperty naming a quantity a ComponentType needs from its context, `surfaceArea`, `iCa`) share one owlready2 attribute, so the slot yields both kinds at once. `get_children` links only the references, which are the ones that have a node to link to.
- One release version for GitHub, docker, the docs and PyPI. `tvbo/__init__.py` holds it in PEP 440 (`x.y.z`, or `x.y.z` + `aN`/`bN`/`rcN`); `make print-tag` spells it as the semver tag (`1.0.0rc1` → `v1.0.0-rc.1`) that docker's semver image tag and the docs image pull parse and PyPI normalises back to the same version. `make release` tagged a candidate `v1.0.0rc1` (no docker version image, docs published over the live site) as the Latest release, and ranked `1.0.0rc1` above `1.0.0`; it now publishes a candidate as a GitHub pre-release, orders versions as PEP 440 does, and checks a new version against the highest published release, candidates included, and a `BUMP=` on a candidate releases it where the candidate already sits at that level (`0.9.0rc1` → `0.9.0`, as npm's `semver.inc` bumps; it used to skip to `0.9.1`); every tag-triggered publish first runs `make check-tag`, refusing a tag in any other spelling.
- A tuning algorithm applies its `apply_every` (the report showed it and every iteration updated anyway), and a mean-aggregated observation whose `tail_duration` spans several `simulation_period`s averages over that many periods instead of being cut to one; a span that is not a whole number of periods, and one that would have to carry across stages, raise.
- `reduce: streaming` with a trailing window (`tail_duration` / `tail_samples`) folds only that window; it averaged the whole run. A streamed reducer that cannot gate on a tail refuses one at codegen.
- A `tail_duration` on an observation that also declares a recording `period` spans the declared time when a streamed reducer or a tuning loop folds it. Both fold every integration step and were handed the window in periods, so a 20 s tail at a 720 ms period averaged 28 steps. A `tail_samples` with such a period on a streamed observation is refused, since it counts samples the reducer never sees.
- A post-scan per-node aggregation (`aggregation: mean`, `last`, … over a model variable) declares its axes `(variable, node)`, so `sel: {node: ...}` finds its nodes; an explored run labelled them `(node, mode)`.
- Generated docstrings keep recipe text as written: in the TVB, JAX, RateML and tvboptim templates `\tau` became a TAB and `\sin` an invalid escape.
- A panel letter on the top-left corner moves the y axis's exponent label to its right instead of printing over it.

### Breaking
- `coupling:` on a simulation experiment is gone as a *declaration*. Declare it under `network:`, where a coupling function has a connectivity to act over. `network.coupling` is keyed by name, so a recipe moves the block one level down and names it: `network: {coupling: {Linear: {...}}}`. An edge still names one by reference. `SimulationExperiment(coupling=...)` raises rather than being ignored. Reading is unaffected: `experiment.coupling` is a read-only property answering the network's first coupling, which is the one a backend expressing a single coupling renders — codegen asks `BaseAdapter` for it instead, so no template derives its own. `scripts/migrate_experiment_coupling.py` performs the move: it reports by default and rewrites under `--apply`, moving only the coupling's own lines so the rest of a hand-authored recipe is left byte for byte as written. It carries anchors onto the re-keyed line, expands a `network: *alias` into a `<<:` merge, and names the file to edit when the network arrives by `!include`. A site it cannot place unambiguously is reported and left alone.
- A key repeated in one YAML mapping is now an error rather than a silent last-one-wins override.
- A serialized entity's `requires` is a list of labels. It used to be a list of storids, which are opaque per-session integers that do not survive a reload.
- A text slot refuses a structured value. A mapping, list, set or record written where the schema declares a string or a name reference (`xlabel: {value: ...}`, `model: {name: JansenRit}`, an edge's `coupling: *anchor`) raises a `TypeError` naming `Class.slot` instead of storing its `str()`. Write the text itself: `model: JansenRit`, `coupling: linear`.
- An experiment that declares observations raises `NotImplementedError` when its backend returns a trajectory carrying no observation at all, instead of reporting success with every observation dropped. That covers python, julia (DifferentialEquations.jl), NetworkDynamics.jl, pyrates, ModelingToolkit.jl, gillespie, neuroml, cuda, the PDE runner and tvboptim's heterogeneous-network path; the ones that know up front refuse before running.
- An `iri` always points at its curated database entry, and every other field the record states, `name` included, overrides that entry at the leaf. A record stating both `name` and `iri` used to skip the entry, so `Dynamics(name="Generic2dOscillator", iri="tvbo:Generic2dOscillator", parameters={"a": 2.0})` held one parameter and no equations. A scalar shortcut overrides only the value: `parameters: {a: 2.0}` keeps the curated parameter's definition and domain. No `name` is needed beside an `iri`, and one naming no curated entry takes the `iri`'s local name.
