## Unreleased

### Added
- `Dynamics.check_backend(format)` and `tvbo validate backend MODEL` read the code a backend generates back into SymPy and compare each state variable's derivative with the specification (`tvbo.analysis.backend_check`): `equal`, `differs` with a point where the two disagree, or `unread` naming a construct the reader does not interpret. Readers cover the jax, numpy, tvb and tvboptim outputs through Python's `ast`, Julia through tree-sitter (installed with `tvbo[julia]`) and NeuroML/LEMS through the XML parser. A sample point where only one side is a finite real number counts as a difference, an input the code fixes to a constant is named in the verdict, and Julia's Euler number is read only as `ℯ`, the constant Julia defines. All 647 golden references with state variables read back equal.
- **Each software entry records the framework names the generated code depends on.** `SimulationTool` gains `modules`, the importable modules of the tool, and `interfaces`, one `SoftwareInterface` per import, attribute, call, keyword argument or base class the generated code takes from it, with the version it was checked against and whether that version documents it as deprecated (`replaced_by`). `tvbo.codegen.inventory` reads the names from generated Python and Julia, and `scripts/update_software_interfaces.py` files them from the golden corpus and every curated experiment: 45 for TVB, 76 for tvboptim, 14 for DifferentialEquations.jl, 4 for BifurcationKit.jl, 3 for PyRates and 1 for NetworkDynamics.jl. The A-box mints each as an individual linked from its tool by `tvbo_sw:interfaces`, at the tool's IRI with the name as its fragment (`tvbo:software/TVB-Optim#…InstantaneousCoupling(incoming_states=)`), so the IRI keeps resolving to the tool's page after codegen stops using the name; a model base class is linked to the TVBO class it implements by `tvbo_sw:realises`. `tests/test_codegen_inventory.py` fails when a template starts using a name its tool's entry does not record.
- `tvbo doctor` resolves every recorded interface against the installed packages and exits non-zero on a name the installed version no longer provides, a recorded keyword the callee now only takes through `**kwargs` included; `--strict` fails on a deprecated one too. A weekly workflow (`drift.yml`) runs it against the newest framework releases and keeps one open issue with the drift, updated when the drift changes and closed once every name resolves again.
- `tvbo mcp` serves the curated database, the software network and the backend check to agents over the Model Context Protocol on stdio (`tvbo[mcp]`, MCP SDK 2.3). `explore` searches every curated record and recorded framework name by words and answers an unmatched query with an empty list; `describe` returns the record behind an IRI; `render` and `check_backend` show and check a curated model's generated code. Every tool is read-only.
- `scripts/spec_gaps.py` reports the specification slots no module or template names, and those only one backend names, over the 604 slots a `SimulationExperiment` reaches: 63 and 45 today, the second mostly algorithm and inference settings only tvboptim reads.
- **A network's BIDS entities name a subject's connectome: `BidsEntities.subject`, `session` and `space`.** A BEP017 export already named a subject-level connectome `sub-<subject>[_ses-<session>]_space-<space>_…`; the record now declares the three entities it reads them from, so a validated network can carry them, and a lookup or a query reads them as `sub`, `ses` and `space`.

### Changed
- **One I/O layer.** Every array file tvbo reads goes through one store per format (`tvbo.data.array_formats`: HDF5, Zarr, NumPy `.npy`/`.npz`, MATLAB v5 and v7.3, delimited text split by what its suffix means) registered beside the export formats (`ArrayFormat` in `tvbo.export.registry`), and `read_array` is the one function a matrix outside a companion is read with: it returns a DataArray under declared dims, never dims taken from the shape, transposes an edge matrix by name onto the receiver-row convention every backend reduces with (`W[i, j]` is the edge `j -> i`), and accepts an undeclared square matrix only when it is symmetric. `File` gains `dims` and `delimiter`, so `edge_matrix_files: [{path: W.csv, dims: [source, target]}]` declares a sender-row file; a bare path must be symmetric. `LazyArrayStore` holds a store instead of switching on the suffix, so a `data_file` may be any of those formats, and a CSV companion, a CSV for each array the sidecar names, reads through a store of its own (`CsvCompanionStore`). The TVB zip importer, the new `from_tvb_h5`, the BIDS BEP017 loaders (`from_bids` and `load_from_bids` share one read), the connectome builder, the atlas centres file and the surface mask read through it, and TVB zip, TVB h5 and BIDS are registered importers (`tvbo import`, `ExportFormat.renderer` optional). Nothing transposes a connectivity with `.T` any more: the two sender-row emitters convert by name (`sender_row`), and `tests/test_edge_orientation.py` sends one directed edge through every format, importer and backend.
- **One generated form.** The datamodel is generated as Pydantic models only: `hatch_build` no longer runs LinkML's Python generator, `tvbo/datamodel/schema.py` is gone, and `linkml-runtime` is no longer a runtime dependency (`linkml` stays build-time); `rdflib`, which it brought along and `tvbo.analysis.bifurcation` reads the ontology with, is declared instead. `tvbo.utils.yaml_loader` is a `yaml.SafeLoader` with the duplicate-key check, the merge-key and `!include` idioms, and builds the named class with `model_validate`; `tvbo.utils.to_dict` and `to_yaml` state a record one way; `tvbo.utils.from_yaml` and `tvbo.utils.pydantic_loader` are removed, their callers reading `yaml_loader.load`/`loads` and `to_yaml` (the platform client included; the text-blob splitting and Odoo reference collapsing the loader did on its own are not carried, a platform export states lists and names as the schema does). The REST API sidecars are the record's own dump. The dialect no longer carries `install_on_dataclasses` or `peer_module`; behaviour that builds members imports the one datamodel lazily. The golden dump corpus is one corpus, `tests/reference_data/database`, holding the Pydantic dumps; the two-form tests (`test_linkml_compatibility`, `test_pydantic_loader`, `test_text_slots_refuse_structure`) are removed or ported to the one form, and docs pages import from `tvbo.datamodel`.
- **`Network` and `SimulationExperiment` are the generated classes.** Their runtime bodies are behaviour mixins (`tvbo.behaviour.network.NetworkBehaviour`, `tvbo.behaviour.experiment.SimulationExperimentBehaviour`) that `hatch_build` attaches to the generated models, as every other class's already was, so a network nested in a recipe, an experiment a study builds and a hand-built object are one class; the `__class__` patches, `Network.from_datamodel`'s copy and `SimulationExperiment.setup_monitors` are gone, and `from_datamodel` is the one `YamlDocument` classmethod, copying each member. What the constructors rewrote before construction is a `mode="before"` validator (`Network`: a top-level `iri` as the `data_file` source, a string `parcellation`, the atlas and tractogram names an `iri` implies, the edge-variable aliases; `SimulationExperiment`: a minted `id`, the dynamics conveniences and `iri` expansion). What they did after construction is `settle()`: a network's node count and placeholder nodes, its `edge_matrix_files` matrix, the default `conduction_speed`, the materialised connectivity and the single-node default; an experiment's name checks, the `model`/`dynamics` mirror, curated observation models, the default network and its couplings, the default and ontology-populated integrator. A record built in Python settles on construction, as before; one a document loader builds reads as written until the loader settles it (`tvbo.utils.source.as_written`), so `yaml_loader.load` and the golden dumps see the record the file states, `load_network` attaches its companion before settling (replacing the private `_defer_connectivity` keyword), and `Network.as_data_file_reference` builds a reference that names a companion not yet written. A `nodes` list keyed by `label` stays the record's nodes until the network is settled, when it is applied to the nodes the network's data materialises.
- **The runtime is built on the generated Pydantic models.** `tvbo.datamodel` exports `tvbo.datamodel.pydantic`; `tvbo.Network` and `tvbo.SimulationExperiment` subclass those models, and every other class in `tvbo.classes` is the Pydantic class with its behaviour mixin. A record validates on construction and on assignment (`extra="forbid"`, `validate_assignment=True`), so a misspelt slot or a value of the wrong type is refused where it is written rather than at the backend. `tvbo.datamodel.schema` (the LinkML dataclasses) still exists for the two-form tests and is retired in a following release; `tvbo.datamodel.tvbo_datamodel` and `tvbopydantic` both name the Pydantic module.
- An unset multivalued slot is `[]` or `{}` on both forms (`hatch_build._with_empty_collections` gives every `Optional[list|dict]` field an empty default factory), so `for x in record.slot` and `record.slot[key]` no longer need a `None` guard; dumps are unchanged, since empties are omitted.
- Unit canonicalisation (`Hz` for `hertz`, `ms` for `millisecond`, …) is a dialect fold, `dialect.canonicalize_units`, driven by the generated `UNIT_SLOTS` table for every slot ranged over `UnitEnum`, and `UnitEnum` resolves an alias in `UnitEnum("millisecond")`; the dataclass `__post_init__` hooks and the enum metaclass that did this for one form are gone.
- A list slot's one member may be written bare on both forms (`output: x`, a `nodes` mapping that spells one node's own fields): `dialect.wrap_lists`, driven by the generated `LIST_SLOTS` table, wraps it. LinkML's dataclasses did this themselves; the Pydantic models refused it.
- A slot assigned after construction holds what the same value gives at construction: `node.state = {"V": 0.1}` is the keyed `StateValue` `V`, a keyed member written without its `name` takes its key, a list-spelled keyed collection is keyed, a unit is made canonical, a terse distribution is completed and a bare list member is wrapped (`dialect.fold_slot`, called from the generated models' `__setattr__`). Pydantic validated an assignment without the dialect, so these spellings raised on assignment. The folds that need the whole record, `iri` expansion and reading `nodes` as a mapping among them, stay with construction. An assignment also leaves the record's other slots as they were: Pydantic hands the dialect validator the whole record on an assignment and keeps what it returns unvalidated, so the validator only checks the record there, where it used to fold it again and an unrelated assignment brought back a deleted curated parameter as a raw mapping.
- A number or a path written in a text slot is read as its text, as LinkML's dataclasses read it: an unquoted `7` in a cohort's `members` is the identifier `"7"`, and `Dataset(bids_root=Path(...))` holds the path's text. A mapping or a list there is refused, and so are `True` and a sympy expression, which the dataclasses stored as their `str()`: write the text itself.
- A list of records in a keyed collection (`Dataset.cohorts: [Cohort(...)]`, `SimulationExperiment.observations: [Observation(...)]`, `Provenance.digest`) is keyed by its members' identifier attribute, as a list of mappings already was.
- Every node written without an id carries the unassigned sentinel until the network's declared nodes are applied, replacing the runtime's detach-and-restore of label-keyed nodes around the datamodel constructor.
- `Edge.coupling` is declared `range: Coupling, inlined: true, any_of: [string, Coupling]`, so an inline coupling on an edge validates as a `Coupling` on both forms; the runtime's detach of inline edge couplings before the constructor and their reattachment after it are gone.
- `from_datamodel` is one `YamlDocument` classmethod restating the record's set fields; the per-class copies (`Coupling`, `Perturbation`, `Study`, `Function`, `Dynamics`), `Dynamics.to_pydantic`/`from_pydantic`, `SimulationExperiment.setup_monitors` (wrote a slot that does not exist) and `Network._prepare_for_datamodel`/`_reattach_inline_couplings` are deleted; `Network.to_yaml`, `Dynamics.save_model_metadata`, `Atlas` and `Study` serialise through `tvbo.utils.to_yaml`.
- A keyed member written as a bare scalar fills the slot its class declares (`state: {theta: -0.3}`, `template_variants: {replication: <file>}`, `digest: {sha256: …}`, `options: {tangent: bordered}`): `StateValue.value`, `LayoutTemplateVariant.template`, `Digest.value` and `Option.value` carry the `simple_dict_value` annotation `Parameter.value` already had, so both forms read it. LinkML's dataclasses filled the first non-key slot of any member class, so `sel: {x: 3}` landed in `Argument.description`; a scalar member of a class that declares no such slot is refused.
- A class-local `unit` (`Edge`, `MeasureSpec`, `NamedArray`, `Argument`, `ExplorationAxis`, `TimeSeries`, `NDArray`, `SpatialField`) has the shared open range, `UnitEnum` or text, so it is canonicalised like the shared slot (`millisecond` is recorded as `ms`, `kg/ms^2` as written).
- The generated models take keyword arguments only: `Dynamics("x")` in the PyRates pages is `Dynamics(name="x")`.

### Fixed
- **LEMS output that jLEMS refused or misread is fixed.** A `Piecewise` condition is lowered to arithmetic on `H` of a difference (`H(H(x - 0.5) - 0.75)` for `x > 0.5`) instead of `H(x .gt. 0.5)`, which jLEMS cannot load because its `H` takes a number; `TentMap`, `PomeauMannevilleMap`, `Hopfield` and `Epileptor` now load. `pi` and `E` are written as numbers, since LEMS has no such constants, and `min` and `max`, which it lacks too, as the same arithmetic on `H`. An equation that reads the model time `t` inside a dimensionless component type divides it by the `SEC` constant. A call to a function LEMS lacks (`atan2`, `erfc`) is refused with the list of LEMS's functions rather than emitted, and so is a model with more than one mode, whose mode axis the NeuroML backend does not lower: `EpileptorCodim3`, `EpileptorCodim3SlowMod`, the four reduced-set models and the two Zerlaut models no longer render to LEMS, and their NeuroML golden references are gone. Of the 112 curated models, 101 render to LEMS and integrate in jLEMS with finite output.
- A model with no state variables (`neuroml__HH_KineticScheme`) is refused by every template format instead of emitting code with an empty destructuring, and the Julia output of a model that declares `functions` (`ZerlautAdaptationSecondOrder`) loads `SpecialFunctions` for them.
- A misspelt key is refused with the slot it may mean on the generated models too: `Integrator has no key 'stepsize' (did you mean 'step_size'?)` is the message of the `ValidationError`, where 0.9.1 raised it as a `TypeError` from the dataclass constructor.
- A study runs the experiment `get_experiment` materialises for each of its records, so a network named by `iri` is resolved before the run; `runtime_experiment` took every record for a materialised experiment once the record's class carried `run`, and `SimulationStudy.run` on such a study failed with `None is not a valid value for jnp.array`.
- A network that states `number_of_nodes` beside nodes declared by `label` applies the declaration to the nodes its generator or source materialises; the count's placeholder nodes replaced it.
- A keyed member written with nothing after its key (`coupling_inputs: {c_in: }`) is the member of that name, and a keyed collection written as a list of one-key mappings (`parameters: [{weight: {value: 0.8}}]`) is keyed by them, as the dataclass loader read both.
- A record holding a NumPy scalar or array in a free-valued slot (a parameter `value` a TVB import fills) serialises: `to_yaml` writes it as the number or list it is.
- `File.name` is the class's own optional slot, so LinkML's Python generator accepts the schema again; the shared `name` identifier cannot be made optional by `slot_usage`.
- `from_tvb_h5` and `from_tvb` read TVB's `orientations` beside `cortical`, `areas` and `hemispheres` through one table (`TVB_NODE_FIELDS`), and skip a per-node array that does not hold one entry per node.

### Removed
**1.0 clears the deprecation backlog rather than carrying it.** Every name that warned in 0.5.x is gone; each had a replacement that was already the documented path, and the callers in `tvbo/`, `tests/` and `docs/` are migrated to it.

- `Dataset.bundle` and the `--bundle-dataset` flag of `tvbo workflow slurm|snakemake|nextflow`: every kit bundles its data (see Changed). Drop `bundle:` from a dataset; `--bundle-select` still picks the variant a kit carries.
- `noise: {intensity: ...}` — the schema slot is removed, so a recipe that still declares it is rejected instead of silently read as a standard deviation. Use `parameters: {sigma: ...}`, or `parameters: {nsig: ...}` if the value was a dispersion (the two differ by sqrt(2D)/D). One reader, `utils.noise_sigma`, now knows exactly two spellings.

The flag sampled every variable's raw domain regardless of what the model declared. `plot.dynamics` spread its multi-trial starts through that flag; it now does so itself, which is where a plotting concern belongs.
- `Dynamics.to_lems()`, `SimulationExperiment.to_lems()` and `save_model_specification()` — use `NeuroMLAdapter(...)`, which emits validated XML rather than a `lems.Model` and covers constructs those never did.
- `Network.compute_delays()` → `calculate_delays()`; `Dynamics.add_coupling_term()` → `add_coupling_input()`; `Connectome` → `Network` (it was a subclass that added a warning and nothing else).
- `Coupling.inner_coupling`, `region_mapping`, `regional_connectivity`, `aggregation` and `distribution`, and the `RegionMapping` class. A record that still carries one is refused at load, naming where its meaning is written now: a coupling on the subnetwork, `node_mapping` on the network, or the coupling of an up or a down edge.
- `Parameter.free` and its `DerivedParameter` copy. A parameter is named where it is acted on: a fit's `free_parameters`, an update rule's `target_parameter`, a continuation's `free_parameters` or `held_parameters`, or an exploration's `space`; a record that still carries `free` is refused at load. An algorithm without introspectable update rules persists no `estimate__` output.
- `tvbo-tvboptim-optim.py.mako` and `tvbo-tvboptim-sim.py.mako`, which nothing included or called, and their `TEMPLATES` keys `optim` and `sim`.
- `equation.piecewise2numpy()` / `piecewise2julia()` — use `codegen.code.render_expression(expr, format=...)`. `print_Piecewise` is the one handler every printer shares, emitting through each printer's `_where3` primitive (`<mod>.where` for numpy/JAX, `ifelse` for Julia). A spec names it as `tvbo:models/JansenRit`, `tvbo:coupling_functions/Linear`, `tvbo:themes/default`, and an atlas by its BIDS stem (`tvbo:atlases/tpl-MNI152NLin2009cAsym_atlas-DesikanKilliany_dseg`). Models move from the root (`tvbo:JansenRit`) into `models/` in the ontology; the 54 files in `models/julia/` take their `name:` as file name (`hodgkin_huxley.yaml` is `HodgkinHuxley.yaml`), so their IRIs read like the rest; and the software schema module's terms move from `software/` to `sw/`, so no schema term shares a path with a record. The singular scopes (`tvbo:observation/…`, `tvbo:theme/…`, `tvbo:experiment/…`) still resolve, with a `FutureWarning` naming the folder form; a record's `name:` and its stem in another case still resolve, though neither is a term; and an unscoped name still resolves where its slot's class makes it unambiguous. `tvbo migrate-iris` rewrites all three into the canonical form.
- The study-layout directory role `code` is `code_source`, after the recipe slot whose default it is; the directory is still `code/`. linkml-runtime 1.12 makes each enum member an instance of its enum, and a member named `code` hides the enum's own `code` property, so the datamodel stopped importing. Ask `study_path("code_source")`.
- LinkML's floor is 1.12.1 for the build's generator and for the runtime alike, so the datamodel is generated by the release that loads it.
- A network that names a source for its connectivity and lists an edge between two of its own nodes is refused at load. Write the edge as a layer entry (no `source`/`target`) or as a route (`source_network`/`target_network`), or drop the source.
- `tvbo workflow nextflow` refuses a `workflow.nextflow` slot it writes into no file (`mem`, `time`, `cpus_per_task`, `gres`, `partition`, `account`, `modules`, `venv`, `setup` and the like). State it as a process directive through `options`.
- `Figure.spines` is an enum (`open`, `box`); any other string is refused at load instead of being ignored at render.
- A route names its parent network `parent`. `source_network: ..` and `target_network: ..` are refused at the edge that carries them.
- A panel's `legend` with no place given takes the theme's `legend_loc` (the backend's `best` where the theme states none) instead of a hardcoded `best`.
- `coupling:` on a simulation experiment is gone as a *declaration*. Declare it under `network:`, where a coupling function has a connectivity to act over. `network.coupling` is keyed by name, so a recipe moves the block one level down and names it: `network: {coupling: {Linear: {...}}}`. An edge still names one by reference. `SimulationExperiment(coupling=...)` raises rather than being ignored. Reading is unaffected: `experiment.coupling` is a read-only property answering the network's first coupling, which is the one a backend expressing a single coupling renders — codegen asks `BaseAdapter` for it instead, so no template derives its own. `scripts/migrate_experiment_coupling.py` performs the move: it reports by default and rewrites under `--apply`, moving only the coupling's own lines so the rest of a hand-authored recipe is left byte for byte as written. It carries anchors onto the re-keyed line, expands a `network: *alias` into a `<<:` merge, and names the file to edit when the network arrives by `!include`. A site it cannot place unambiguously is reported and left alone.
- A key repeated in one YAML mapping is now an error rather than a silent last-one-wins override.
- A serialized entity's `requires` is a list of labels. It used to be a list of storids, which are opaque per-session integers that do not survive a reload.
- A text slot refuses a structured value. A mapping, list, set or record written where the schema declares a string or a name reference (`xlabel: {value: ...}`, `model: {name: JansenRit}`, an edge's `coupling: *anchor`) raises a `TypeError` naming `Class.slot` instead of storing its `str()`. Write the text itself: `model: JansenRit`, `coupling: linear`.
- An experiment that declares observations raises `NotImplementedError` when its backend returns a trajectory carrying no observation at all, instead of reporting success with every observation dropped. That covers python, julia (DifferentialEquations.jl), NetworkDynamics.jl, pyrates, ModelingToolkit.jl, gillespie, neuroml, cuda, the PDE runner and tvboptim's heterogeneous-network path; the ones that know up front refuse before running.
- An `iri` always points at its curated database entry, and every other field the record states, `name` included, overrides that entry at the leaf. A record stating both `name` and `iri` used to skip the entry, so `Dynamics(name="Generic2dOscillator", iri="tvbo:Generic2dOscillator", parameters={"a": 2.0})` held one parameter and no equations. A scalar shortcut overrides only the value: `parameters: {a: 2.0}` keeps the curated parameter's definition and domain. No `name` is needed beside an `iri`, and one naming no curated entry takes the `iri`'s local name.
