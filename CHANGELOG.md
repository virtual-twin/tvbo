## Unreleased

- The Events section of an experiment report writes every stimulus whose waveform the result container records (`stimulus_waveforms`) as a display equation `name(t) = ...` above the events table (`report.event_equations`), and the table leaves the effect of each event shown there (`shown_above`) out of its row, states each parameter with its unit and gains an "Applied to" column with the nodes an event names and their weights.
- A reference to a network layer that routes to another network (`used: {iri: tvbo:networks/<sensors>, output: gain}`) resolves: the array's `node_j` carries the labels the layer states in `dimension_labels` (the regions) and `node_i` the network's own nodes (the sensors), where both axes took the network's node labels before and a sensors-by-regions gain matrix was refused for its shape.
- The API's `POST /experiment/run` runs on the current result API: a `duration` or `step_size` the request states replaces the specification's own, and one it leaves out keeps the experiment's, the experiment is built with `SimulationExperiment(**spec)` and run on the requested backend (JAX by default), and the response carries the state trajectory as time by variable by node by mode, read from `SimulationResult.to_timeseries()` with its time axis, sample period, state-variable names and region labels. The endpoint still called a result interface that no longer exists, so every run from the platform's experiment builder failed.

- A heatmap whose two axes run over the same index set, such as a structural or functional connectivity matrix or a delay matrix, is drawn in a square frame; a parameter grid keeps the shape of its slot, and an `aspect` or `box_aspect` the panel declares still wins. An FC matrix in a tall slot used to be stretched into a rectangle.

- The clinical graph reaches the Jansen-Rit model Stefanovski et al. (2019) ran: `study-Stefanovski2019` now `usesNodeDynamics` `models/JansenRit`, beside its `model-JansenRit` survey entry, so a query from the study arrives at a runnable model and its parameters.

- `tvbo[knowledge]` holds setuptools below 81: pybel imports `pkg_resources`, which setuptools 81 removed, so a fresh install of the extra failed on `import pybel`.

- `references.bib`: 295 author fields written as "Surname AB" are now "Surname, A. B.", so citation styles read surname and initials correctly (APA printed "A et al." for Spiegler A); the stray `date` of Jirsa2017 that overrode its year is removed.

- A trimmed spine ends on its outer tick or, where the data drawn inside the view runs past that tick, at the data's end, so no line hangs beyond the axis that measures it (a declared window such as 20160 to 60480 ms with ticks from 30000 used to leave the first third of the trace without an axis).

- Figure animations hold their axes still: before the movie is drawn, every autoscaled axis is measured over up to 60 frames and each frame is pinned to the union of those extents, so the theme's axis rule places the same limits and ticks on every frame while trails grow and slices move; declared limits are untouched.
- **DifferentialEquations.jl, ModelingToolkit.jl, the python backend and gillespie open on a declared initial-state distribution.** The two Julia backends, the python network runner and gillespie opened every state variable at its `initial_value` without a word, and a single-node python run drew on seed 0 rather than the run's seed. DifferentialEquations.jl and ModelingToolkit.jl now draw each declared state variable with the Julia NetworkDynamics.jl draws it with (`initial_state_draws`), from one `MersenneTwister` seeded with the distributions' own seed, else the run's, and refuse distributions that resolve to two seeds; python, on one node or a network, and gillespie open on `get_initial_values` on the run's seed, the draw tvb and jax open on. The benchmark's single-node MontbrioPazoRoxin cells on julia, modelingtoolkit and python now open `r` on a uniform draw on [0, 2] rather than at 0.1.
- **A parameter drawn over time is refused where no step draws it.** A dynamics, coupling or event parameter whose `distribution` declares `axis: time` is a stochastic input. tvboptim drew a dynamics parameter and the one such parameter of a stimulus that is an equation of time at every step; every other backend, and tvboptim for a coupling parameter, a state-triggered, recorded or sourced event's, or a second one on one event, integrated it at its `value` without a word, or, on NetworkDynamics.jl, drew a dynamics parameter once per node. A backend now refuses such a parameter by name, when it renders or runs, unless the export registry lists that kind as one it draws at every step (`StartKind.TIME`, `COUPLING_TIME`, `STIMULUS_TIME`, `EVENT_TIME`); tvboptim lists `TIME` and `STIMULUS_TIME`, no other backend lists any. This takes over NetworkDynamics.jl's own refusal of a dynamics parameter (G248). No curated model, experiment or study declares such a parameter on a backend that now refuses it.
- The built-in surface panel reads `opacity` from its options and hands it to bsplot as the mesh's transparency, so a custom panel can lay a painted cortex over what it has already drawn (a network inside the brain) and keep it visible. It is not yet an attribute of the `Surface` class, so a `surface:` block cannot state it.
- A network panel colours its edges by connection weight with `edge_color: weight`: every edge takes its place on a ramp from a faint `base` to the theme's `ink`, so a weak connection recedes and a strong one stands out without a second colour scale beside the one the nodes use.
- A surface panel places per-region values on any surface atlas templateflow carries, not only Desikan-Killiany: a region of the surface atlas answers to `ctx-<side>-<region>`, `ctx_<side>_<region>` and its bare name, compared without case, so `surface_atlas: Schaefer2018` or `Destrieux2009` paints a connectome keyed by the matching tvbo atlas, and across `hemi: both` each hemisphere is joined through its own name list.
- Figures: a channel that names a sibling variable (`encoding.x: event__I` on a layer whose output is the integration) follows the plotted array along the axes they share, so under an animation the sibling is cut to the same frame or trail instead of being drawn whole against one sample ("x and y must be the same size"). A point of a run can now be plotted against the input an event gave it at that moment.
- **The edges of a `kind: network` panel are drawn behind the nodes in front of them.** Every connection tube ran as one piece from node centre to node centre, so the depth sort drew it over the spheres it ends in, and spheres and tubes were coarse enough to show their facets at a large `node_size`. The panel now ends each tube at the surfaces of its two spheres, builds it in sections (bsplot's `edge_trim` and `edge_segments`) and draws spheres and tubes at a finer mesh.

### Added
- **A colour role can name one of the palette's hues: `highlight: palette.5`.** A theme that `!include`s another and moves one role onto a hue it already lists writes that colour once, in the list, and the role follows the hue if the list changes.
- **Horizontal bars: `mark: bar` with its categories on `y`.** A bar layer whose encoding names `y` and no `x` draws one horizontal bar per entry of that channel, so long category names (model families, atlases) read level instead of rotated into each other.
- **An animation can show a stretch of a long run: `Animation.window`.** `window: [start, end]` keeps the frames inside that interval of the animated dimension, read in its own coordinate, so a run kept twenty minutes long for a correlation matrix is shown one minute at a time from the same realisation. A figure whose only moving layer is a `frame: cursor` rule over static traces animates too: a cursor layer is measured for the frame count, since it marks the frame at its own coordinate.
- **Masses on springs as a figure panel: `kind: spring`.** A built-in panel draws one mass per entry along a layer's `color` dim (a node, a swept parameter, a seed), or one per layer, on coil springs at the displacement the layer holds, through `bsplot.mechanics`; `spring:` (`Springs`) mounts them hanging, lying, as a chain of coupled oscillators between two walls or on a ring, sizes each box by a mass coordinate and labels each spring. The masses take the colours a line fan over the same dim takes, so a mass and its trace beside it agree, and the rest position is the experiment's own rest state at each entry's swept parameters, so a loaded spring's shifted rest is computed rather than typed. Under an animation the masses move with the frame while the frame holds still.
- **The vector field of the experiment's own model: `mark: stream`.** A layer with `mark: stream` and `encoding: {x: <state variable>, y: <state variable>}` draws the field of the dynamics the bound experiment ran, read from its result sidecar (`tvbo.plot.field`), as streamlines coloured by speed with its equilibria marked, over the panel's `xlim`/`ylim` or the range the run covers. Off-plane state variables are held at their initial values and a swept parameter takes the selected cell's value. Under an animation it is the static backdrop unless declared otherwise, and the field is computed once per figure, not per frame.
- **A scatter coloured by an axis of its array fans like a line.** `mark: scatter` with `color:` naming a dimension (or a coordinate along one) draws one cloud per entry in the colours the line fan over that dim takes, so the dot riding on each animated trace matches it; a `color:` naming a quantity per point still shades one cloud. The two fans share one colour rule (`_fan_entries`).
- **A network panel draws the connectome on the brain, as bsplot draws a brain network.** `kind: network` renders through bsplot's `plot_network_on_surface`: a sphere per region and a tube per kept connection, depth-sorted with a translucent fsaverage `plot_surf` cortex in `surface_color` at `surface_alpha`, seen from above, the front or the left by `projection`, so network and surface panels share one camera and one shading. A per-region layer colours the spheres; a layer with one value per pair of regions (`node_i`, `node_j`, such as an analysis returning the weights or the tract lengths) colours the tubes, placed by label along both axes, while the spheres take `color`. `node_size` and `edge_width` are now radii in millimetres; `node_edge_color` and `node_edge_width`, which a sphere has no use for, are gone. `label_size` sets the type of the node names, written where `bsplot.surface.view_coords` puts each centre, and with no `connectome` named the panel draws the network its layer's experiment ran on, the copy the run freezes beside its result.
- **A run keeps the stimulus it was driven with: `event__<name>`.** A result container that holds the recorded trajectory also holds every equation-defined stimulus event evaluated on the same time axis (`tvbo.data.types.stimulus_signals`), the waveform before its per-node weights, so a figure draws the drive beside the response from one container (`used: {experiment: 132, output: event__I}`) instead of retyping the pulse. A data-driven event (`dataLocation`) is already a file and is not copied.
- **A figure layer reads a container named by its file.** `used: {iri: <path to a _result.h5>}` resolves in the figure adapter as `tvbo.data.dataref` already resolved it, from the working directory or the study root, so a figure draws a run that lives in another study tree (a manuscript replication shown in a lecture) without copying the container.
- **An unlabelled axis is selectable by name: `tvbo.data.dataref.index_bare_axes`.** A `sel:` on an axis the container wrote without a coordinate (a sweep's `point`, the `node` axis of a network that named no regions) numbers that axis `0 .. n-1` first, in the emitted figure script, a custom panel's `load_layer` and `select_labeled` alike, where it used to fail with xarray's "no associated coordinate". A labelled axis keeps its labels.
- **A layer can trail through an animation: `frame: trail`.** An animated layer declared `trail` is drawn from the start of the animated dimension up to the current frame, in the grammar and in a custom panel's `load_layer` alike, so a phase-plane orbit or an optimiser's path grows as it is traced where `slice` would leave one dot.
- **A swept trajectory of one recorded variable names its node axis `node`.** An exploration that records a single state variable stacks each cell as `(time, node)`, and the positional template used to call that second axis `variable`; the grid now takes its axis names from what the sweep records and the saved node axis carries the node names, so a figure selects a region of a sweep by label as it does for an unswept run.
- **A labelled histogram for a study analysis.** `callable: {module: tvbo.analysis.distributions, name: histogram}` counts the finite entries of a labelled array into equal bins and returns the counts on a `bin` dimension whose coordinate is the bin centre, so a figure draws the distribution of a connectome's tract lengths or delays with `mark: bar` and `encoding: {x: bin}` and no study code of its own. Entries outside `lo`/`hi` are left out, which keeps the zeros of a connectivity matrix out of the picture.
- **The clinical layer is counted from the ontology: `tvbo.ontology.clinical`.** `clinical_landscape()` reads the clinical application studies of the shipped merged ontology with SPARQL and returns the distinct studies per clinical domain and node dynamical model as a `(domain, model)` array, the studies per domain with each domain's ICD-11 code and chapter as coordinates, and the totals of studies, domains and models, shaped as a study analysis callable so a figure binds the landscape by dimension and its numbers grow with curation.
- **The biological grounding is counted from the ontology: `tvbo.ontology.grounding`.** `go_grounding()` reads every link from a TVB-O entity to a Gene Ontology term out of the shipped merged ontology and returns the links and grounded entities per domain (parameter, state variable, derived variable, dynamics, concept) as labelled arrays beside the five totals, shaped as a study analysis callable so a figure's bar panel binds them by dimension instead of a script counting them beside the paper.
- **A channel names a component of any variable in the container.** `encoding: {x: x}` on a layer whose `used` selected `variable: v` out of the same array resolves `x` as that array's other component, so a phase plane is two slots on one layer (`sel: {variable: v}`, `encoding: {x: x, y: integration}`) and needs neither a transform nor a second recording. Before, a name that was neither a coord of the selected array nor a sibling variable was refused.
- **A theme names its raised face and its monospace: `Palette.surface`, `Theme.mono_font`.** `surface` is the colour of a legend box, an inset or a card standing on the `background`, applied as `legend.facecolor` and exported with the other roles, so a document drawn from the theme (the documentation site, a slide deck) and its figures agree on what a layer looks like. `mono_font` is the typeface list code and identifiers are set in, the backend's monospace family. The shipped `tvbo:themes/default` states its surface.
- **A panel can draw no y axis: `Panel.hide_yaxis`.** The y spine, ticks and tick numbers go and the x axis stays, for a trace read for its shape rather than off a scale, such as one row of a stack of recordings that share only their time axis. `frame: false` strips both axes; this strips one.
- **An annotation sets its own weight: `Annotation.font_weight`.** `font_weight: bold`, the slot a `Theme` sets the body text's weight with, sets one label heavier than the figure's text, as a row label naming what the row shows.
- **tvboptim draws a stimulus parameter over time by the shared reading.** The per-step draw of a stimulus parameter declared with `axis: time` was uniform whatever family the distribution named, keyed by its own seed or else 0, and drew between -1 and 1 where the distribution declared no domain. It now reads the declaration as a parameter start does (`start_draw`, on the run's seed): a Normal is drawn as a normal, a distribution without a seed follows `execution.random_seed`, and a family, bound or moment no draw takes is refused naming the parameter and its event. A Uniform with its own seed and domain, as ReservoirComputing B declares its driver, draws the sequence it drew.
- **A backend with no stimulus path refuses a declared event.** DifferentialEquations.jl, ModelingToolkit.jl, gillespie and the CUDA kernel read no event the experiment declares, and the continuation backends (BifurcationKit.jl, AUTO-07p, PyRates with AUTO-07p) none either; each ran the unstimulated model, or continued it, without a word. The export registry now says how a backend treats a declared event (`ExportFormat.events`: integrated, dropped, or continuation), and a backend that does not integrate one refuses it by name, naming the backend and the event, when it renders or runs, whether the event is declared with a target or read by name in an equation. A model's own events, a spike's reset among them, are part of the model and not affected. No curated model, experiment or study declares an event on these backends.
- **The CUDA kernel draws its noise from the run's seed.** `curand_init` was seeded with the work item's index plus the GPU's cycle counter at launch (`clock64`), so two runs of one recipe drew different noise and no recipe could repeat a noisy run. The kernel now seeds every work item from `execution.random_seed` on a subsequence of its own, and a launch that resumes at a later step, as the PyCUDA driver's chunked launches do, starts past every draw the launches before it could have made. No curated experiment or study runs a noisy experiment on cuda.
- **The CUDA kernel draws the noise the experiment declares.** A noisy kernel added `nsig * curand_normal(...)` with `nsig` declared nowhere, so it compiled only for a model that carried a parameter of that name, read that parameter as the spread of each step's increment with no `sqrt(dt)`, and never read the integration's or a state variable's declared amplitude. Each state variable's amplitude now comes from `noise_sigma_array`, the reader every backend shares, so `sigma` and the dispersion `nsig` mean what they mean elsewhere, and the kernel adds `sigma * sqrt(dt) * N(0, 1)` after the Euler step, the increment tvboptim adds for its additive noise; a state variable without noise takes no draw. No curated experiment or study runs a noisy experiment on cuda.
- **A container kit's GPU experiment runs on the GPU.** The published image installs JAX with its CUDA 12 plugin, through the new Linux-only `cuda` extra, so one image serves CPU and GPU nodes, and each engine's Apptainer/Singularity call (the Slurm scripts, the Snakemake profile's `apptainer-args`, Nextflow's `singularity.runOptions`) carries `--nv` when an experiment of the kit declares `accelerator: gpu` or a GPU `gres`. Such an experiment was granted a GPU node and integrated on its CPU, because the image held a CPU-only JAX and the container saw no GPU. A kit that asks for no GPU keeps its flags, and an `--nv` already in `container_args` is not repeated.
- **The array vocabulary sums onto slots, ranks under a mask, and multiplies a comparison: `scatter_sum`, `spearman`.** `scatter_sum(values, index, size)` adds each value into the slot its index names, as `numpy.add.at` accumulates, so a per-corner field of a mesh's faces sums onto the vertices. `spearman(x, y, mask)` is Spearman's rank correlation over the entries where the mask is nonzero, ties given their average rank, and equals `scipy.stats.spearmanr` of the kept entries; what a left-out entry holds, NaN included, changes nothing. A comparison that arithmetic applies to, `(p <= alpha) * mask`, reads as 1 where it holds and 0 where not (`parse.expression.array_syntax`) in `parse_eq`, an observer's equations and an analysis `equation:`, where SymPy refused it before. Each prints one expansion for numpy and jax, so an analysis on the host and an observer in the loop compute the same Spearman.
- **A producer reads labelled inputs its experiment declares, and one call can give an observer many constants: `Function.outputs`.** A `producer:` argument declared with `used:` arrives as the labelled array it names, so the producer pairs its entries with nodes by label, and its labels key the cached call with its values. The reference counts among the experiment's own (`SimulationExperiment.declared_references`, over every producer the experiment declares, an observer's constants among them), so a plan orders the experiment after an experiment the producer reads, a kit stages the analysis container it reads, and a run binds its network to the run's results directory, which is where a run of the kit finds that container. A `Function` lists the arrays its callable returns in `outputs`, and a producer naming it by `iri` takes the list (`FunctionCall.outputs`): stating no `output:`, it is a bundle, and an observer binds each array as a constant of its own name, all read from the one cached artifact (`param_io.materialise_bundle`); a `partition.over` naming the bundle stands for every output, and an output named like another symbol of the observer is refused, naming both. `Histogram` lists its five outputs.
- **The fixed operators of a triangulated mesh that a wave detector reads, as a curated producer: `tvbo:functions/MeshOperators`.** `producer: {iri: tvbo:functions/MeshOperators}` builds them once per group of a mesh's vertices (a hemisphere), padded to the largest group and bound under twenty names: the face table, each face's gradient basis and area, the pseudo-inverse Poisson operator, each vertex's k-ring faces with the multiplicity of Koller et al. (2024), the ideal divergent field of the heat-method geodesic distance, the border masks of the wave test's null family and deciding vertices, a reference node field and the group labels. Mesh vertices meet network nodes by label, and no order of the inputs changes a value. `tvbo.analysis.mesh.mesh_operators` needs the new extra `tvbo[mesh]` (libigl, potpourri3d) where the producer runs.
- **Resampling tables for the tests of a wave detector, as curated producers: `tvbo:functions/NodePermutations` and `tvbo:functions/SpinPermutations`.** Each returns `index`, a table of `n` rows over the network nodes in gather form (a node field permuted by row r is `x[index[r]]`), and `group`, the group label of each node. Every row moves the nodes of each group (a hemisphere) among themselves and never into another group: `NodePermutations` by a uniform permutation, as Koller et al. (2024) permute each hemisphere's phases, and `SpinPermutations` by a random rotation of the sphere positions it is given followed by the nearest node of the same group, as BrainSpace's `SpinPermutations` reassigns them, the same rotations turning every group. A study declares the seed and the number of rows, groups are keyed by label, and no order of the nodes or the groups changes a table. `tvbo.analysis.mesh.node_permutations` and `spin_permutations` need neither libigl nor potpourri3d.
- **A group connectome by consistency-based thresholding: `tvbo:functions/ConsistencyThreshold`.** An analysis naming it reduces a cohort's connectomes, stacked on `subject` as a cohort read or a per-subject network returns them, to one: each region pair's mean weight over the subjects, kept for the share `density` of all region pairs whose coefficient of variation across subjects is lowest (Roberts et al. 2017, doi:10.1016/j.neuroimage.2016.09.053), and mirrored; lengths, when given, are averaged the same way and kept on the same pairs. A network layer reads the result through `used: {analysis: <name>, output: weight}`, so a study declares the group connectome of its own subjects in the recipe. On a random cohort it equals the construction Koller et al. (2024) released, transcribed in the tests (`tvbo.analysis.connectome.consistency_threshold`).
- **Built-in `histogram` and `joint_density` panels.** `kind: custom` with `render: histogram` draws a `tvbo:functions/Histogram` container's `count` as bars that each fill the bin its `edge` gives, so no bar width derived from the data is typed into a spec; `percent: true` draws each count as a percentage of the values counted. `render: joint_density` draws two quantities of the same entries as a hexagonal-bin density with each one's distribution on its margin (`marginal: hist`, `kde` or `both`) and, with a declared `colorbar`, a scale of counts; `mincnt: 0` draws the empty cells too, as seaborn's hex jointplot does. Two layers are x and y, paired by label along the dimension they share, or one layer gives y and its `encoding.x` coordinate x. Neither needs `code_modules`.
- **A surface panel draws a mesh an analysis derived: `Surface.used`.** `surface: {used: {analysis: <name>}}` reads the mesh from that analysis's result container, its `vertices` (V, 3) and `faces` (F, 3), the way a layer reads its data, so a parcel mesh or a reconstructed surface needs no file written out by hand and the figure's render rule waits for the analysis. When the vertices carry region labels, a layer's values are placed on them by label: a layer stored in another order lands on the right vertices, one over fewer regions leaves the rest missing (drawn in `missing_color` when declared), and a label that is no vertex is refused by name. A binding that names an `output`, a `sel` or a `transform`, or a mesh named a second way as well, is refused.
- **A surface panel draws its values as dots at the vertices: `Surface.markers`.** With `markers: true` the layer is drawn as one sphere per vertex over the mesh rather than painted onto its faces, the way a brain plot of region centres shows a parcellated quantity. The dots are depth-sorted with the mesh in one pass, so the mesh hides the dots on its far side, and each sits on the surface, raised by its radius along the vertex normal. They are unlit, so a dot's colour is the colour on its bar; the mesh under them is flat, in `color` or else the page colour, and a vertex without a value gets a dot in `missing_color`. `marker_size` is the radius in the mesh's units, half the median edge length when unset. `markers` without a layer, or beside `geometry: true`, is refused.
- **A standalone colour bar's `ticklabels` without `ticks` mark the bar's ends.** The labels were handed to whatever ticks the backend had placed, first label to first tick, and that tick can lie beyond the bar: `ticklabels: [low, high]` printed "high" partway along the bar and "low" nowhere, with only matplotlib's warning that ticks may be mislabeled. Labels without `ticks` are now spread evenly from the bar's lower end to its upper end, so two labels mark its two ends, and `ticks` and `ticklabels` of different lengths are refused.

### Fixed
- **A figure's only panel can fill its cell.** `fill_cell: true` on the one panel of a single-panel figure (a captured graph, a schematic) grows it to the figure frame; it used to fail on an empty union of neighbours.
- **A captured page keeps its query.** An `image` panel whose `source` is a local page with a query (`full-graph.html?join=0`) now loads that page with the query, so one page captured in several states needs no copy per state; the query used to be percent-encoded into the file name. Staleness still follows the one local file.
- **A panel's `plain` tick format writes ticks in full.** `xtick_format: plain` or `ytick_format: plain` on one panel now drops matplotlib's offset as well as its exponent, so ticks at 1000.0 and 1000.1 read as such and not as 0.0 and 0.1 with `+1e3` at the corner, which is what the theme-wide `plain` already did.
- **An mp4 figure keeps the page colour.** The movie writer converted RGB with ffmpeg's default BT.601 matrix and left the stream untagged, which browsers decode as BT.709, so a dark background came back two levels off and showed as a faint box on the slide; the conversion and the stream tags are now BT.709, limited range.
- **A declared x window fits the y range to what it shows.** A panel that declares `xlim` and no `ylim` infers its y range from the lines inside the window, not from an onset transient or an excursion the window hides; a reference line spanning the axes does not count, and the axis stays autoscaled, so the theme's axis rule still places its ends. Figures whose lines reach outside their declared `xlim` draw at a tighter y range than before.
- **An animated figure's still shows the frame it declares.** The still was saved after the movie, and matplotlib's finished animation redrew frame 0 into it on the savefig draw, so `still: 100` printed the first frame; the still is now saved before the movie is written.
- **A swept trajectory of several variables keeps their names.** An exploration that records more than one state variable writes its `results` with the variables it records (`output_names`) on `variable`, where the axis was positional only, so a figure selects `variable: x` from a sweep as it does from a single run.
- **A row of a connectivity matrix paints a brain map.** A `surface`, `volume` or `network` layer selected to one `node_i` or `node_j` of a per-edge matrix, a region's connectivity profile, keeps that axis's region labels, and the panel places it by label as it does a per-node vector; before, only a `node` coordinate was read and the row was refused as unlabelled.
- **A sibling component follows the line it is drawn against.** `encoding: {x: x}` on a layer selected to `variable: v` and fanned over `node` (or any other axis) now takes the `x` of the same node for each line, where it took every node's `x` at once and drew each orbit against all of them. The component is selected at the plotted line's scalar coordinates before it is squeezed.
- **A kit freezes the script a run renders.** `tvbo workflow` froze each experiment's backend script with `render`, which takes the couplings' declared `delayed` as it stands, while a run renders through `render_code`, which configures the experiment first and turns every coupling's `delayed` off when the network's delays all vanish (an infinite conduction speed, or tract lengths of zero). Such a kit's frozen script integrated a delayed coupling at zero delay, which reads the incoming states from a history buffer that opens on the dynamics' default state rather than the drawn initial state and that `coupling_evaluation: per_stage` does not re-evaluate within a step, while a spec-mode run of the same experiment integrated an instantaneous coupling, so the two gave different trajectories where `run()` promises identical ones. The freeze now renders through `render_code`, so the frozen script is the code a run renders.
- **A kit says when it cannot freeze an experiment's script.** A backend script that fails to render at freeze leaves the kit to run that experiment in spec mode, re-rendered on the node; this was logged at info level and passed unnoticed, and it is now a warning naming the experiment and the error.
- **A delayed run reads its own opening over its first max-delay window.** On tvboptim the history buffer of a delayed coupling was filled when the run was prepared, from the dynamics' default state on every node, and the generated script then wrote the opening (an initial-condition draw, a node's declared `state`, a seeded operating point, the working-point ramp, an `initial_conditions.<sv>` cell, each trial of an `n_trials` ensemble) into the current state alone, so for as long as its longest delay such a run, or the settle before its measured window, coupled the default states instead of its opening. TVB, as tvbo runs it, fills the history with the opening. Every site that writes an opening now refills the delay lines from it (`_refill_history`), a trial inside the mapped function from its own draw; a settled run's measured window still reads the settle's trajectory, and a run that opens at its declared `initial_value` integrates bit for bit as before.
